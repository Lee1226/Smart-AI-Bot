# AI 整理 XMind / Markdown 用例

在测试套件列表选择「AI 整理后导入」，选择文件和目标平台，再生成草稿。
已有套件也可以在详情页点「AI 整理用例」。使用当前账号设置的 Agent 模型和凭证。

AI 会区分分类、前置条件、操作和预期，合并重复操作与同一页面的多个检查项。
不同条件、互斥分支应保留为独立用例；不确定的入口、冲突和性能计时要求会列在「需要确认」中。
整理目标平台用于约束文档内容，不代表已具备对应平台的设备执行能力。

草稿展示原始用例数量、整理后的操作及检查项，以及每个检查项对应的原用例编号。
可以修改名称、应用包名、前置条件、操作和预期，通过「对照原始内容」核对语义。
确认后另存为新套件，不修改原套件或运行记录。取消草稿不会创建套件。

保存后的步骤树为「用例（含前置条件）→ 连续操作」，预期附在相应操作节点上。
同一操作的多个预期作为一个检查点整体校验；来源、原始用例、整理说明和待确认事项
保存在用例参数中，可随套件 JSON 导出。不自动执行生成的用例。

每条原用例必须被至少一个检查项引用。遗漏、未知来源编号、空的最终预期、
模型异常或格式错误都会阻止保存。来源覆盖检查不能证明语义正确，仍需核对草稿。
计时要求会保留，但执行时需要独立计时证据，不能只凭截图判定通过。

当前一次整理支持最多 100 条原始用例、10MB 文件和 50,000 字符的模型输入。
超过限制请拆分文件。原样导入仍然可用。
